# Local judge A/B: Qwen 2.7 vs Holo4 (2026-10-24)

Two judging jobs run on the GB10 next to the planner: the **step-outcome judge** (`expect` strings in multi-step batches: did the screen end up as the plan said) and the **Enter gate** (before a Return that follows typed text: did the text land in the input the task wanted). Both were scored against hand labels on frames captured through the Pi.

| judge | step-outcome (n=20) | Enter gate (n=8) | latency step / gate |
| --- | --- | --- | --- |
| Qwen 2.7 (vLLM :8000) | 19/20 | 8/8 | 0.7 s / 1.1 s |
| Holo4 (vLLM :8010) | 19/20 | 4/8 | 0.3 s / 0.4 s |

Holo4 is a grounder: it is good at "is X on screen" and poor at the task-conditional judgement the gate needs (half of its gate errors were a chat composer approved for a search task). Qwen 2.7 stays the gate, verifier and lesson-writer; Holo4 stays the grounder for the grounded loop only and is off on the main path.

Caveats: the gate set here (n=8) is separate from the earlier three-scenario gate check in the README (5/5 each on a chat composer with a search task, the same composer with a posting task, a browser address bar; Qwen 2.7 only). The labelled frames lived in `/tmp` and were lost in the OOM reboot the same evening (a sweep of GUI-Owl/Fara/MAI-UI as a third vLLM); the tallies above are from the run log before the reboot. The set should be rebuilt (~25 gate cases) before any further judge comparison.
